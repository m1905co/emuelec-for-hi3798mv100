# Hi3798MV100 双系统（Android + EmuELEC）完成报告

**日期**：2026-10-13
**设备**：Hi3798MV100（板级 `hi3798mdmo1d_hi3798mv100_ddr3_2gbyte_8bitx4_4layers_emmc`，1GB DDR）
**状态**：✅ 双系统双向切换实测通过

---

## 1. 核心结论：必须换 p1 的 U-Boot

| | 安卓原厂 U-Boot（618,444 B） | mv100 纯 U-Boot（539,272 B） |
|---|---|---|
| `Android_Main` / `boot from kernel` | 有 | **无** |
| `bootimg` 命令 | 有 ×3 | **无** |
| `boot-recovery` / `first\|second-recovery` | 有 | **无** |
| `RSA Verify the kernel` / `recovery verify OK` | 有 | **无** |
| `bootcmd` 是否被执行 | **否**（硬编码从 p11 取内核） | **是** |
| 内核来源 | p11 固定 82MiB，**只读 10 MiB**，按 Android boot.img 解析 | `bootcmd` 指定的任意偏移 + `bootm` |

**⇒ 同一台机器、同一个内核（`hi_kernel.bin` md5 `56e3bcf2…` 与原厂完全一致），
区别只在 U-Boot。** 之前所有"改 env / 改 bootcmd / 绕 10MiB / 造 boot.img / 补 DTB"的尝试
都是在这台 U-Boot 的能力边界内打转，从根上走不通。

## 2. 最终架构

```
p1  @0MiB      1MiB    ← 纯 U-Boot（mv100/fastboot.bin，写 557,056 B）
p2  @1MiB      4MiB    ← env：偏移 0x100000 处 64KiB，bootcmd + bootargs 决定启动谁
p10 @58MiB     24MiB   ← +0x800       EmuELEC 内核 uImage（原厂未改动）
                          +70MiB(0x23000) 安卓 ramdisk 的 uImage 包装（329,280 B）
p11 @82MiB     12MiB   ← Android boot.img（原厂，内核 + 音频/根 ramdisk）
p13 @102MiB    340MiB  ← EmuELEC rootfs（ext4）
```

**切换 = 把对应的 64KiB env 块写进 p2 起始处 + 重启。**

## 3. 两套 env

### EmuELEC 模式
```
bootargs = mem=1G mmz=ddr,0,0,256M vmalloc=500M console=ttyAMA0,115200 \
           root=/dev/mmcblk0p9 rootfstype=ext4 rootwait panic=10 \
           blkdevparts=mmcblk0:1M(fastboot),4M(bootargs),16M(recovery),1M(deviceinfo),\
           4M(baseparam),4M(pqparam),4M(logo),68M(fastplay),340M(storage),-(userdata)
bootcmd  = mmc read 0 0x10000000 0x1D000 0x6000; bootm 0x10000800
```

### Android 模式
```
bootargs = coherent_pool=2M console=ttyAMA0,115200 \
           blkdevparts=mmcblk0:1M(fastboot),4M(bootargs),16M(recovery),1M(deviceinfo),\
           4M(baseparam),4M(pqparam),4M(logo),16M(fastplay),8M(misc),24M(factory),\
           12M(kernel),8M(iptv_data),340M(backup),340M(cache),520M(system),-(userdata) \
           mem=1G mmz=ddr,0,0,400M
bootcmd  = mmc read 0 0x10000000 0x29000 0x6000; \
           mmc read 0 0x11000000 0x23000 0x400; \
           bootm 0x10000800 0x11000000
```

公共项：`baudrate=115200 bootdelay=3 verify=n ethaddr=00:07:63:83:02:12`
`ipaddr=192.168.1.10 netmask=255.255.255.0 gatewayip/serverip=192.168.1.1`
`stdin/stdout/stderr=serial`

**存储格式**（与 `saveenv` 实测一致）：
`[4 字节小端 CRC32(覆盖 [4,64KiB))][NUL 分隔的变量][0x00 填充到 64KiB]`

## 4. 怎么切换

| 当前系统 | 命令 |
|---|---|
| EmuELEC | `/usr/bin/switch-to-android` / `/usr/bin/switch-to-emuelec` |
| Android | `/data/a4/switch-to-emuelec` / `/data/a4/switch-to-android` |

两个脚本都是"`dd` 写 p2 + `sync` + `reboot`"，需要 root。
（安卓侧：`adb shell /data/a4/switch-to-emuelec`，或终端里 `su` 后执行）

---

## 5. 关键坑与解法

1. **EmuELEC 的 root 必须"叫" `mmcblk0p9`**
   `/usr/bin/histb-storage-guard` 会检查 `/sys/dev/block/<id>/uevent` 里 `DEVNAME=mmcblk0p9`，
   且拒绝 `mmcblk0p13`。**解法**：`blkdevparts` 的顺序决定分区编号 —— 让前 8 项累加正好等于
   rootfs 的物理起点 102 MiB（`1+4+16+1+4+4+4+68 = 102`），第 9 项 `340M(storage)`
   就落在 102MiB 起 340MiB —— 正是我们的 rootfs。
2. **`mmz` 必须 256M**：用 60M 时视频硬解报 `VDEC_AllocPreBuffer failed`
   （需要约 150MB pre buffer）。`vmalloc=500M` 与厂商一致。
3. **安卓的 ramdisk 必须包成 uImage**：`bootm` 拒绝裸 gzip（`Wrong Ramdisk Image Format`）。
   已包装为 `type=3(ramdisk) comp=0` 存到 p10 的 70MiB 处。
4. **安全网**：env 里 `bootdelay=3`（纯 U-Boot 认得，安卓那个不认）→ 上电有 3 秒可用
   Ctrl+C 打断进 U-Boot 提示符；`panic=10` 让 root 挂载失败时自动重启回提示符。

## 6. 恢复手段

- **p1 原厂备份**：`emuelec/work/p1p2_backup/p1_cur.bin`（也等于 `emuelec/backup/bk/p01.bin`，
  md5 `d4d00576f8ea32469bb382502156337d`）。写回：
  `dd if=p1_cur.bin of=/dev/block/mmcblk0p1 bs=512 count=2048`（Android 侧）
  或 `dd if=/dev/mmcblk0 bs=512 seek=0 ... `（EmuELEC 侧）。
  ⚠️ 写回后 `bootcmd` 就又失效了。
- **进 U-Boot 提示符**：上电后 3 秒内连发 Ctrl+C；或把 p10 里的 uImage 头改坏（boot 失败会自动落提示符）。
- **原厂 recovery**：按住遥控键上电 → recovery → 刷 SD 卡上的 `update.zip`
  （会重写 p11、并 `format ext4 by-name/backup` = 抹掉 p13 的 EmuELEC rootfs）。

## 7. 已知限制 / 待办

- **EmuELEC 没网络**：盒子只有 WiFi，Linux 侧驱动不了；`eth0` 无链路 → DHCP 失败。
  要联网（SSH/下载 ROM）需要**给盒子插网线**。
- **TF 卡**挂载在 `/media/emuelec-tf`，提示 `layout=missing EmuELEC/ directory` ——
  想用 TF 卡做 ROM 库需要在卡上建 `EmuELEC/` 目录结构。
- **看画面需要接电视**（当前未接；supervisor 与 EmulationStation 进程、日志均已验证在运行）。
- **control**：目前只有 TTL 串口（COM4/CH340, 115200）能操作 EmuELEC；
  插网线后可用 SSH（22 端口）。
- 之前那个 `A4DualBoot.apk` 的动作模型（p8/p10→p11）已过时，可改为调用
  `/data/a4/switch-to-emuelec`。
