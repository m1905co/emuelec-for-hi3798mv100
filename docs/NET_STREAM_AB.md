## 2. UV vs STOCK 对比

**只取视频在播的 #1–#3：**

| 对比方式 | STOCK | UV | Δ |
|---|---|---|---|
| 相邻切换 #2(STOCK) → #3(UV)，后 1/3 中位 | 85 °C | 84 °C | **−1 °C** |
| 稳态段 mean（#2 vs #3） | 84.2 | 84.0 | **−0.2 °C** |
| #1(UV, 冷态起步) vs #2(STOCK, 稳态) | 84.2 | 81.4 | +2.8 °C ⚠️ |

**#1 那个 "+2.8 °C" 是假象**：#1 是实验刚起步、机箱还冷（此前设备空闲），#2 已进入热稳态；这不是电压效应。**剔除热漂移后的真实差值 ≈ 0 ~ 1 °C。**

⇒ **降压 60 mV（1140→1080）在网络流场景下几乎没有可测收益。**

## 3. 温度趋势（重要）

按 2 分钟采样的序列：

```
UV#1:   82 → 81                      (冷态起步)
STOCK#2: 83 → 84 → 84 → 84 → 84 → 84 → 84
UV#3:   84 → 84 → 84 → 84 → 84 → 84 → 84
STOCK#4: 86  ← 视频就在这附近停了
（停播后）82 → 78 → 75 → 73 → 72
```

**网络流播放的稳态平台 ≈ 84 °C**（波动范围 81~86），**并不是持续爬升**——进入稳态后 20 多分钟基本平在 84。设备没有逼近 90+ °C。

对比历史：
- 本地 4K 文件播放（当贝 + 厂商解码器）：80~86 °C
- 纯 4 核 CPU 满载 @1.0 GHz：热饱和 97~98 °C

⇒ **网络流的解码负载远低于 4 核满载，温度平台与本地播放基本一致。**

`out/net_logcat_20261011_145044.txt`（14 620 行）里的关键行：

```

```

- **`HISI_OMXVDEC` = 海思硬件视频解码器 OMX 组件**，`OMXNodeInstance` 是 MediaCodec 侧节点
- `IJKMEDIA` 14 条 + `IjkMediaPlayerClient` 64 条 ⇒ 确实由 **ijk** 驱动
- `HiMediaPlayer` / `MediaPlayerService` **各 0 条** ⇒ **没有走厂商播放器** ✅

**结论：用户看到的确实是 ijk 走 MediaCodec → OMX → 海思硬解的路径。**

## 5. 结论

1. **降压在网络流场景下无实用收益**：同频下 60 mV 压差对应温差 ≈ **0~1 °C**，与本地视频的 1~2 °C 结论一致。原因不变——CPU 动态功耗只占整机 ~20%，而网络流的热主要来自 **VDEC / VPSS / DRAM 视频管线 + Wi-Fi**，降压打不到。
2. **网络流稳态温度 ≈ 84 °C**，未见 90+ °C。此前"播视频冲到 90+ °C"的记忆，本轮**未复现**。
3. **ijk 硬解已确认**（HISI_OMXVDEC 证据），与厂商解码器路径一致。
4. 吞吐仅 **340~420 KB/s**，说明所播片源码率不高（很可能非 4K）；**若换成 4K 高码率 HEVC 网络流，VDEC 负载会明显上升**，温度有望更高——这是唯一还没测到的场景。

## 6. 局限与后续

- #4 阶段因视频停止而无效；真正的 video-on 阶段只有 3 段。
- 存在明显热漂移：实验在 60 min 内从冷态走到稳态，跨段比较要小心。
- **未测**：4K 高码率网络流（>5 Mbps）。要验证"能不能到 90 °C"，需要用户播 4K 片源、并持续 ≥ 90 min。
