# 蓝牙 / 红外 硬件与驱动结论

**日期**：2026-10-14
**设备**：Hi3798MV100（mdmo1d）

---

## 一、蓝牙：**这台盒子没有蓝牙硬件**

### Android 侧取证（权威判据）

| 检查项 | 结果 |
|---|---|
| `ls -l /dev/rtk_btusb` | **No such file or directory** |
| `ls /sys/class/bluetooth/` | **空**（无 `hci0`） |
| `dmesg \| grep -i bluetooth` | 只有协议栈初始化：`RFCOMM/BNEP/HIDP socket layer initialized`，**没有任何控制器** |
| `usbcore: registered new interface driver btmtk_usb` | 仅驱动注册，**未匹配到硬件** |
| `lsusb`（EmuELEC / Android） | 只有 `0bda:0179`(WiFi) 与 hub |

`init.bigfish.rc` 里虽然有 `service blueangel /system/bin/mtkbt`、`chmod 0660 /dev/rtk_btusb`、`insmod btusb.ko` —— 但那是海思 **SDK 通用配置**，不代表本机装了硬件。**Android 本身都没跑起来蓝牙，所以不是 EmuELEC 的问题。**

### EmuELEC 内核侧（顺带结论）

`modules.builtin` 内建：`bluetooth / btusb / btintel / bnep / hidp / rfcomm`
—— **只有 USB 蓝牙**，没有 `hci_uart` / `btmtk`（即不支持 UART 蓝牙）。

⇒ **蓝牙结论：硬件不存在，无需也不可修。**

## 二、红外：**硬件有、内核驱动也有，只差用户态程序**

### 2.1 硬件存在（Android 取证）

`/proc/bus/input/devices`：
```
I: Bus=0000 Vendor=0001 Product=0001
N: Name="Hi keyboard"
H: Handlers=sysrq rfkill kbd event0
B: KEY=ffffffff ffffffff ... (全键掩码)
```
`Bus=0000` = **SoC 内建**（非 USB）→ 这就是**红外遥控接收器**。

### 2.2 EmuELEC 内核**已经带 hi_ir 驱动**（关键发现）

| 检查项 | 结果 |
|---|---|
| `/sys/module/hi_ir` | **存在**（模块已加载/内建） |
| `/proc/kallsyms` | 有 `ir_first_read_key` |
| `/proc/msp/ir` | **IR 协议全表 Enabled**（NEC / RC6 32/20/16bit / TC9012 / Sony d7c8/d7c5 / 常熟/惠州/德州变体…） |
| `/dev/hi_ir` | **字符设备存在** |
| `/usr/lib/libhi_msp.so` | **存在**，导出完整 `HI_UNF_IR_*` API |
| 内核符号冲突验证 | 用补丁过 vermagic 的 `/kmod/hi_ir.ko` 试加载 → 报 `exports duplicate symbol ir_first_read_key (owned by kernel)`，**反证内核已内建 hi_ir** |

`/proc/msp/ir` 还显示按键缓冲状态：
```
Key getting info: Get(Try/OK) : 0/0
Key buffer: 500 keys, Reader 0 / Writer 0
```
→ 驱动在跑、缓冲就绪，**只是还没有程序去读它**。

### 2.3 缺的那一环：用户态读取程序

Android 用的是 `ir_user`（13,656 B）→ 调 `HI_UNF_IR_*`（实现在 `libhi_msp.so`）→ 转成输入事件。

**问题**：Android 的 `ir_user` 是 **bionic** 二进制（`INTERP=/system/bin/linker`，依赖 `libc.so/libstdc++.so/libm.so/libhi_msp.so/libhi_common.so/libutils.so/libcorkscrew.so` 等 13 个 bionic 库）。
已做实验：把 linker + 全部 13 个依赖打进 `/system/`，**链接成功但运行 `Segmentation fault`**（bionic libc 在非 Android 内核上的兼容坑）。

### 2.4 可行路径（下一步）

| 方案 | 说明 | 可行性 |
|---|---|---|
| **A. 自研 glibc 程序** | EmuELEC 自带 glibc 版 `libhi_msp.so`（导出全部 `HI_UNF_IR_*`）；WSL 已有 `arm-linux-gnueabihf-gcc`，可编译小程序 → 调 `HI_UNF_IR_Init/GetSymbol/GetValueWithProtocol` → 写 `uinput` 生成 `eventX` | **推荐**，需确认函数签名 |
| B. 修 bionic segfault | 继续排查 bionic 环境（`/dev/__properties__`、TLS、prctl） | 中等，坑多 |
| C. 直接 ioctl `/dev/hi_ir` | 反汇编 `libhi_msp.so` 得 ioctl 号与结构体 | 可行，工作量大 |

**注意**：EmuELEC 内核内建了 `uinput`（`kernel/drivers/input/misc/uinput.ko`），方案 A 输出事件没问题。
