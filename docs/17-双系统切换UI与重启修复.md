## 1. 系统内重启黑屏：根因与修复

### 1.1 根因链（全部有日志/实验证据）

```
ES 菜单「重启系统」
  → ES 执行  touch /var/lock/start.retro         ← 请求重置标志
      ✗ 本机 /var/lock 目录不存在 → touch 失败
        （supervisor.log: touch: /var/lock/start.retro: No such file or directory）
  → ES 正常退出 (status 0)
  → supervisor 只打印 "HiSTB EmuELEC exited with status 0" 便自身退出
  → 没有任何组件去执行 reboot
  ⇒ 前端消失、黑屏；只能断电
```

**关键澄清**：**内核重启一直是好的**——`/usr/bin/switch-to-android`（内部 `reboot -f`）从 10-13 起就一直能用。问题纯在用户态"重启请求 → 执行"这条链路断了。

### 1.2 修复（`/usr/bin/histb-emuelec-supervisor` v2）

| 位置 | 内容 |
|---|---|
| 启动 ES 前 | `mkdir -p /var/lock`；清除陈旧标志 `start.retro` / `start.shutdown` / `/tmp/reboot.please` |
| `wait "${frontend_pid}"` 之后 | 若 `start.retro` 或 `/tmp/reboot.please` 存在 → `rm` 标志 + `sync` + `reboot`；若 shutdown 标志存在 → `poweroff -f` |

- 文件 7009 B，md5 `5bc9064fabe0c3ebab7687d61098f072`，`sh -n` 通过
- 备份链：`.a4bak`（原版 4477 B）→ `.a4bak3`（v1 仅输入等待，5593 B）
- 本地副本：`emuelec/work/histb-emuelec-supervisor.{orig,new,v2}`

### 1.3 验证（端到端）

```
mkdir -p /var/lock; touch /var/lock/start.retro; kill <ES pid>
→ supervisor.log:  A4: frontend requested reboot; rebooting now
→ 盒子自动重启；回来后
   HiSTB input devices ready after 0s: event0 event1
   HiSTB EmuELEC builtin passed the 30s process health window
```

## 2. 安卓侧切换 APK（诉求 ③ 上半）

### 2.1 先踩清楚的两件事（都很关键）

1. **本机 `su` 对 App 静默拒绝**：su 是 SuperSU 的（`daemonsu`、`/data/data/eu.chainfire.supersu` 引用），但**SuperSU 管理器 App 并未安装**，`persist.sys.root_access` 为空 → App 调 `su -c id` **无任何输出**（不是报错，是静默拒绝）。
2. **setuid 助手对 App 也无效**：Android 4.4 给 App 进程设 `PR_SET_NO_NEW_PRIVS`，setuid 不提权。实测把 `/system/xbin/a4-switch`（04755）交给 App 执行，输出 `uid/euid : 10023/10023`。
   > ⚠️ 用 `su 10023 -c /system/xbin/a4-switch status` 会得到 `10023/0 (root)`，**这是假阳性**，不能用来验证 App 路径。

### 2.2 最终机制

```
[App, 无任何权限]
   │  写 /data/a4/switch.request  ("emuelec")
   ▼
[a4-switchd, root]  ← /system/etc/install-recovery.sh 开机拉起
   │  exec /system/xbin/a4-switch emuelec
   ▼
[a4-switch, setuid root + CRC32 校验]
   │  校验 env 块 CRC → 写 /dev/block/mmcblk0p2 (64 KiB) → reboot()
   ▼
   U-Boot 按 p2 环境块启动 EmuELEC
```

| 组件 | 路径 | 说明 |
|---|---|---|
| APK | `/system/app/A4DualBoot.apk` | `com.a4.switcher` v4，**已注册为系统应用**（`pm list packages -s` 可见，`pm path` → /system/app/…） |
| 守护 | `/data/a4/a4-switchd` | 轮询 `switch.request`，只接受 `emuelec` / `android` / `reboot` 三个固定值；消费后即删（陈旧文件不会重复触发） |
| 助手 | `/system/xbin/a4-switch` | setuid root；`status/emuelec/android/reboot`；**写前校验 U-Boot env 的 CRC32**，坏块拒绝（U-Boot 自己也是这么校验的） |
| 数据 | `/data/a4/env-{emuelec,android}.bin` | 各 65536 B，CRC 实测：emu `fc2e800f` / android `5d4893fd` |
| 开机钩子 | `/system/etc/install-recovery.sh` | 末尾追加 `sh /data/a4/a4-switchd &`（备份 `.a4bak`） |

### 2.3 验证（真实点击，不是脚本旁路）

```

input tap 1268 652   → 确认弹窗「确认切换」
```

## 3. EmuELEC 侧「重启回安卓」按钮（诉求 ③ 下半）

本机 ES 的脚本菜单机制 = `es_systems.cfg` 里的 system 条目（已有 `diagnostics` 先例）。新增：

```xml
<system>
  <name>switchos</name>
  <fullname>系统切换 / Switch OS</fullname>
  <path>/storage/ee/switch</path>
  <extension>.sh .SH</extension>
  <command>/bin/sh %ROM%</command>
  <platform>ignore</platform>
  <theme>ports</theme>
</system>
```

| 文件 | 说明 |
|---|---|
| `/storage/ee/switch/01-reboot-to-android.sh` | 校验 `/storage/ee/env-android.bin` 存在且为 65536 B → `exec /usr/bin/switch-to-android`（写 p2 + `reboot -f`）；日志写 `/storage/ee/logs/a4-switch.log` |
| `/storage/ee/switch/gamelist.xml` | 菜单显示名「重启到安卓 / Reboot to Android」 |
| `es_systems.cfg`（**两处都改**） | `/opt/emuelec/etc/emulationstation/` 与 `/storage/ee/config/.emulationstation/`，各留 `.a4bak`；本地 XML 校验通过（28 个 system） |

**验证**：ES 日志出现 `Parsing XML file "/storage/ee/switch/gamelist.xml"...` 且**没有** `System "switchos" has no games!` 警告（说明条目带内容、会显示在列表里）；实跑该脚本 → 安卓正常启动（cmdline 为安卓 bootargs）。

> 说明：EmuELEC 的 ES 不支持给任意界面加自定义按钮，脚本菜单项即本平台的「按钮」。

## 4. 手柄拔插（诉求 ②）：机制边界与本次加固

**平台限制（10-14 已取证）**：EmuELEC 的 EmulationStation **只在启动时枚举一次输入设备，不支持热插拔重扫**；拔插后必须重启前端才能重新识别。这不是驱动问题（内核侧手柄一直正常）。

**现有两层**：
- supervisor 启动 ES 前等待 `/dev/input/event*`（避免"手柄晚于 ES 出现"）
- `a4-inputwatch` 守护：检测到"有 joystick 却不在 ES 的 fd 里"→ 自动 `/etc/init.d/S95emuelec restart`

**本次加固**（`a4-inputwatch` v2，md5 `ec41d4eb43bb50e6dffd54eba6a236e6`）：
设备判定从"所有 `/dev/input/event*`"改为**只认 joystick 类设备**（`/sys/class/input/inputN/js*` 存在才算）。
原因：将来 IR 遥控通过 uinput 生成的是**键盘类**设备，ES 永远不会打开它——按旧逻辑守护会认为"有设备没被持有"而**无限重启前端**。

> 观感说明：拔插后前端会重启一次（回到主菜单），这是 ES 不支持重扫的必然代价；从拔插到恢复约 5–15 s。
> 如需真正的"零重启热插拔"，得改 ES 源码（SDL 输入层重扫），属于另一个量级的改动。

## 5. 红外遥控（诉求 ①）：已收敛到最后一环

| 环节 | 状态 | 证据 |
|---|---|---|
| 硬件接收 | ✅ | `/proc/interrupts`：`ir_s2` 中断持续计数 |
| 内核驱动 | ✅ 已内建 | `/sys/module/hi_ir`、`/dev/hi_ir`、`/proc/msp/ir` 全协议 Enabled |
| 数据到达 | ✅ **实测有数据** | `/proc/msp/ir`：`Symbol buffer … Writer at: 334`（Key buffer 0/0） |
| fetch 模式语义 | ✅ 实测 | `SET_FETCH(1)` → `Drive Report Raw Symbols`；`(0)` → `Drive Report Parsed Symbols`。**fetch=0 时 read() 干净阻塞拿不到键** |
| ioctl 协议 | ✅ 反汇编确认 | 模块 ID `0x51`，`(dir<<30)|(0x51<<8)|nr|(size<<16)`；SET_ENABLE `0x40045104`、SET_BLOCKTIME `0x40045106`、SET_FETCH `0x40045109`、ENABLE_KEYUP `0x40045101`、ENABLE_REPKEY `0x40045102` |
| 用户态程序 | ⏳ 待完成 | `emuelec/work/ir/a4-ir.c`（probe/learn/sym/run），已静态编译可用 |

**下一步方案（明确）**：既然驱动在"解析模式"下不下发按键、但**原始符号确实在缓冲里**，改为读原始符号（`fetch=1`）→ 在用户态自解 NEC（leader 9 ms / 4.5 ms + 短 560 µs / 长 1690 µs）→ 经 `/dev/uinput` 出键盘事件给 ES。
需要你按遥控器配合采一次符号样本（每次按键约 2–3 个符号）。
