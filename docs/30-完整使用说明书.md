## 一、设备与双系统

### 1.1 分区布局（eMMC）

| 分区 | 位置 | 大小 | 内容 |
|---|---|---|---|
| p1 | 0 MiB | 1 MiB | U-Boot（双系统切换核心） |
| p5 | 18 MiB | 4 MiB | baseparam（HDMI 输出参数） |
| p10（安卓 `factory`） | 58 MiB | 24 MiB | **EmuELEC 内核**（uImage） |
| p13（安卓 `backup`） | 102 MiB | 340 MiB | **EmuELEC rootfs**（ext4） |
| p14（安卓 `cache`） | — | 340 MiB | 安卓 cache |
| p15（安卓 `system`） | — | 520 MiB | 安卓 system |
| p16（安卓 `userdata`） | — | 剩余 | 安卓 /data（EmuELEC 侧挂成 `/mnt/android`） |

> **关键**：安卓的 `backup` 分区就是 EmuELEC 的系统盘。原厂 OTA 里 `format backup`
> 就是抹掉 EmuELEC 的那一步 —— 本包已改成写入 EmuELEC 镜像。

### 1.2 切换系统

| 方式 | 操作 |
|---|---|
| 安卓 → EmuELEC | 桌面 **「A4 双系统切换」**（`com.a4.switcher`），选 ① 按 OK |
| 安卓 → Recovery | 同一个 App 选 ③（刷机 / 清数据用） |
| EmuELEC → 安卓 | 首页轮播选「系统切换 / Switch OS」 |
| 命令行（安卓 root） | `a4-switch emuelec` / `a4-switch android` / `a4-switch status` |
| 命令行（EmuELEC） | `a4-os-switch android` / `a4-os-switch emuelec` |

切换后会重启，约 40 秒进新系统。

**怎么切的（唯一有效机制）**：原厂 U-Boot 只认 misc 分区（p9）前 32 字节的标记。

```
"product-test"  → mode2 → 从 p10 起 EmuELEC 内核（cmdline 带 root=/dev/mmcblk0p9）
"boot-recovery" → mode1 → recovery
空              → mode0 → 安卓
```

安卓侧 `a4-switch` 是 **setuid(4755)** 的静态二进制，直接写 misc 前 32 字节；
桌面 App 无 root，只往 `/data/a4/switch.request` 写一个词，
由 `/system/xbin/a4-switchd`（root 守护，`install-recovery.sh` 拉起）执行。
**注意**：`install-recovery.sh` 里对 `a4-switch` 的 chmod 必须是 `06755`，
写成 `0755` 会把 setuid 抹掉，App 就切不动了。

## 二、刷机

### 2.1 会刷什么

| 分区 | 结果 |
|---|---|
| system | 原厂 system + 本包 **8 个替换 + 5 个新增** |
| boot / recovery / baseparam / logo / iptv_data | 按原厂包写入 |
| **backup（EmuELEC rootfs）** | **写入 EmuELEC 镜像（含全部优化）** |
| **fastboot（p1，U-Boot）** | **写入"双系统 U-Boot"**（原厂 + cmdline 补丁 `fastboot_a4.img`）；若写原厂版，misc 标记失效 ⇒ 切不到 EmuELEC |
| **factory（p10，EmuELEC 内核）** | **不动** |
| cache / userdata | **format（清空）**，随后放回 `/data/a4` 双系统脚本与 `userdata/app` |

⚠️ **安卓数据会被清空**（应用、账号、WiFi 记录）。刷前自行备份。
✅ **TF 卡不参与刷机**，卡上的游戏/BIOS 原样保留（见 §4.7）。

### 2.2 怎么刷

1. `update_a4_dual.zip` 放 U 盘根目录（FAT32）
2. 断电 → 插 U 盘 → 按复位/短接上电进 Recovery
3. `apply update from USB drive` → 选该 zip
4. 完成后重启，先进安卓（首次开机较慢）

### 2.3 刷完第一次开机（重要）

1. 进安卓 → 连 WiFi（安卓有正常输入界面）
2. 桌面会看到两个图标：**「A4 切换」**（切系统）和 **「温度调节」**（A4Tune，新加的）
3. 切到 EmuELEC：启动时**自动读取安卓已保存的 WiFi**，无需再输入
4. EmuELEC 首页轮播：`favorites | CPU Speed | Network`

> 因为 `format userdata`，安卓的 WiFi 记录没了；EmuELEC 里 `/opt/wifi/wpa_supplicant.conf`
> 是镜像里带的那份（PandoraBox）。你在安卓里连好网后，EmuELEC 每次开机会重新导入。

### 3.2 HEVC / VP9 硬解（已开启，**两处改动**）

| 层 | 文件 | 改了什么 |
|---|---|---|
| 声明层 | `system/etc/media_codecs.xml` | 给 `OMX.hisi.video.decoder` 补 `video/hevc` / `x-vnd.on2.vp9` |
| **代码层** | `system/lib/libstagefright.so` | **3 处等长覆写（共 8 字节），把 ACodec 的 HEVC 支持补回来** |

`libstagefright.so` 的具体补丁（文件大小不变、不动指针、不重排表）：

| # | 文件偏移 | 原 → 新 | 作用 |
|---|---|---|---|
| 1 | `0x0D7087` | `"video/3gpp"` → `"video/hevc"` | `kMimeToRole` 表里 H.263 的槽位让给 HEVC |
| 2 | `0x0CA883` | `"video_decoder.h263"` → `"video_decoder.hevc"` | 组件角色串 |
| 3 | `0x0FB0E4` | `3` → `11`（`OMX_VIDEO_CodingHEVC`） | mime→编码值表，让 ACodec 为 HEVC 请求编码 11 |

- 结果 md5：`1f6a87576834091566fa59f3a3da8e2f`（包里就是这个版本）
- 代价：**H.263 / video/3gpp 解码失效**（机顶盒上无实际用途）
- 原厂解码器 `libOMX.hisi.video.decoder.so` **不用改**（它本来就认 `video_decoder.hevc`）

> 为什么两处都要改：`media_codecs.xml` 只是"告诉系统这个组件支持 HEVC"，
> 真正把请求送下去的是 `ACodec`（在 `libstagefright.so` 里）。厂商把 ACodec 的
> HEVC 行裁掉了，所以只改 xml 会在 `configureCodec` 阶段 `-1010` 失败。

实测（2026-10-10，干净重启）：HEVC 720p / 4K / H.264 回归三个用例 `configureCodec` 失败 0 次、
软解回落 0 次，`HISI_OMXVDEC` 全程 `Executing`，画面能被 `screencap` 抓到
（说明帧写进 App 自己的 Surface，不是硬件 VO 层）。

### 3.5 降压降温：A4Tune App + `a4-uv`

> 设计原则：**不写死在开机脚本里**。默认什么都不做，由你手动开。

#### 用 App（推荐，遥控器可操作）

桌面图标 **「温度调节」**（`com.a4.tune`，10.9 KB）：

| 按钮 | 作用 |
|---|---|
| ① 立即降压 | CPU 1.0GHz @1080mV + core 域 1000mV，AVS off |
| ② 恢复默认 | AVS on，ondemand 600M~1.5GHz，电压交回 AVS |
| ③ 开机自动降压 | 开 / 关（写 `AUTO=1/0`） |
| 刷新状态 | 重新读 `/data/a4/uv.status` 与 `/proc/hisi/msp/pm_cpu` |

**遥控器操作**（不用摸屏幕）：

```
↑ / ↓  移动选中项   →  选中项永远是「琥珀色底 + 黑色文字 + ▶ 前缀」
OK     执行选中项
```

> 为什么不用系统焦点：这个 ROM 在 touch mode 下 `View` 的 focused 状态经常不生效，
> 遥控器按方向键画面毫无变化（老版本就是这样）。现在 App 自己接管 `onKeyDown`，
> 选中项由代码画，跟系统焦点无关，遥控器 100% 可用。

界面上方大字直接写当前状态：

```
● 当前状态：已降压（AVS Off）        绿色
○ 当前状态：原厂默认（AVS On）       橙色
开机自动降压：已开启 / 已关闭  ·  温度 66°C  ·  当前 1000MHz / 1130mV
```

选项上还会标 `✓ 当前生效`，所以**不用点也能看出现在用的是哪一档**。

App 没有 root 权限，也不申请任何 Android 权限，工作方式是：

```
App 写 /data/a4/uv.request   →   install-recovery.sh 启动的 root 守护（a4-uv watch，2 秒轮询）
                             →   真正改 cpufreq / pm_cpu / pm_core
                             →   写 /data/a4/uv.status 供 App 显示
```

> 为什么不直接 `su`：这个 ROM 的 `su` 是 SuperSU 的（`-rwsr-sr-x`），但**没装 SuperSU 管理器**，
> 应用请求 root 会被静默拒绝（双系统切换当初就是因此改成请求文件方案的）。
> App 会先试一次 `su -c`，失败自动落到请求文件，所以点完大约 2 秒生效。

#### 用命令行

```sh
su -c 'a4-uv status'      # 频率 / 电压 / 温度 / 开关状态
su -c 'a4-uv on'          # 立即降压
su -c 'a4-uv off'         # 恢复默认
su -c 'a4-uv auto on'     # 开机自动降压（默认 off）
su -c 'a4-uv temp'        # 只读温度
```

配置文件 `/data/a4/uv.conf`：
```ini
AUTO=0          # 1=开机自动，0=不自动（默认）
CPU_MHZ=1000
CPU_MV=1080
CORE_MV=1000
```
日志 `/data/a4/uv.log`，状态快照 `/data/a4/uv.status`。

#### 实测数据（不是估的）

**安卓 · 4K H265 ijk 硬解负载**

| 配置 | 稳态温度 | 净降 |
|---|---|---|
| 基线（CPU 1140mV Auto + core 1060mV） | 84 °C | — |
| **CPU 1080mV + core 1000mV** | **80.1 °C**（81 样本，15 min，电压零漂移） | **≈ −4 °C** |
| core 单独 1060→1000mV | 79.3 → 77.0 °C | −2.3 °C |
| CPU 单独 1155→1080mV | — | −1.6 °C（三轮 +1.0/+1.8/+2.0） |
| core 980 / 960mV | 77.0 / 77.0 °C | 无额外收益，且 core 域含 DDR，挂死需断电 |

- **GPU 是"在用但不可调"**：Mali 驱动确实加载（`/dev/mali`、`libMali.so` 在 ES 与 RetroArch
  进程里都映射着），RetroArch 走 `video_driver=gl` + `video_context_driver=fbdev_mali`，
  GPU 每帧把 320×224 放大到 1920×1080（实测 `PP_util` 31~37%、`GP_util` 1~2%）。
  但 `pm_gpu` 的 `volt/freq/dvfs` 写入全是 no-op（只有 `avs on/off` 生效），频率恒 200MHz
  且从未升频 ⇒ 不是瓶颈。GPU 的热量只能通过 **core 域**（喂 GPU/VPU/VPSS/DDR）间接降。
- 写法顺序不能变：**钉 `scaling_min=max` → `avs off` → 写 `volt=`**。
  否则内核温度控制线程会把电压还原（实测：切一次 OPP，AVS 自动重开，写的值全丢）。
- 边界：CPU 1.0GHz 实测 1030mV 是硬边界（写 1005 直接挂机），脚本用 1080mV 留 75mV 余量。

**EmuELEC（另一套系统，只能调频，不能调压）**

| 配置 | 温度 | 帧率 |
|---|---|---|
| 1.5GHz / 1495mV（原来的 performance） | 82 °C | — |
| **上限 1.0GHz（默认）** | **63 °C（−19 °C）** | 50 fps（撞 50Hz 输出上限） |
| 上限 600MHz | 54 °C | 47 fps（街机完全可玩） |

> EmuELEC 的 `/proc/hisi/msp/pm_cpu` 是 `-r--r--r--`（只读），所以那边**没有降压**，
> 只有频率挡位（首页 CPU Speed 或 `a4-perf`）。
> 600MHz 掉到 47fps 是"实测结论"，不是"不可用"——街机原生帧率本来就在 50~60，
> 47fps 可玩，换 8~10 °C 的温降，很多人更愿意选它。

### 4.4 手柄热插拔与「遥控」的真实身份（重要，之前漏了）

#### 4.4.1 ES 只在启动时枚举一次输入设备

EmulationStation（SDL2）**开机扫描一次 `/dev/input`，之后永不重扫**
（`/etc/init.d/S94a4-ird` 的注释写得很清楚：`EmulationStation enumerates input devices
once, at start-up, and never rescans`）。

⇒ 冷启动之后再插的手柄，ES **看不见**；已拔掉的手柄，ES 还当它在。
所以「插手柄 → 重启 EmuELEC 才能读到」这个现象是**系统机制**，不是配置错。

#### 4.4.2 已有守护自动处理，不必真去重启整机

`/etc/init.d/S96a4-inputrecover` 在开机时拉起 `/storage/a4-hotplug`（inotify 监听 `/dev/input`）：

| 事件 | 行为（取自程序字符串与实际日志） |
|---|---|
| 新增设备 | `restarting frontend so it re-enumerates` → 给 ES 发 SIGTERM（不服则 SIGKILL），ES 重启一次就认到新手柄 |
| 移除设备 | `removal only, no restart needed`；但若 ES 还持有已删除设备的 fd，会重启一次 |
| ES 没在跑（正在游戏） | `no frontend running, nothing to do` —— **不会打断游戏**，退出游戏回前端时自然生效 |
| 短时间反复插拔 | `%d restarts within %d s, backing off`（防抖） |

实测日志（`/storage/ee/logs/a4-hotplug.log`）：

```
a4-hotplug: added:   event0
a4-hotplug: restarting frontend so it re-enumerates
a4-hotplug: signalling frontend pid 2521
a4-hotplug: watching /dev/input (v4, debounce 800 ms)
```

**所以正常用法是**：插上手柄 → 等 3~10 秒，屏幕会闪一下回到游戏列表（= 前端重启完成）→ 手柄可用。
**手动兜底**（自动没触发时）：

```sh
/etc/init.d/S96a4-inputrecover restart    # 重启监听本身
/etc/init.d/S95emuelec restart            # 只重启前端
reboot                                    # 整机
```

#### 4.4.3 第一次插某种手柄会要求配置

ES 遇到「未在 `es_input.cfg` 里登记过的设备」会弹 `CONFIGURE INPUT`（按提示依次按 A/B/方向/Start 等）。
配一次即写入 `/storage/ee/config/.emulationstation/es_input.cfg`，以后不再问。
目前该文件已登记 3 个设备：

```
A4 IR Remote             030000004d0a00000100000000010000
Microsoft X-Box 360 pad  030000005e0400008e02000010010000
ZhiXu Gamepad            03000000790000001c18000011010000
```

#### 4.4.4 「遥控」其实是一个虚拟手柄

这块板子的 EmuELEC 内核是 `CFG_HI_IR_TYPE_S2`：红外驱动只往 `/dev/hi_ir` 吐原始码，
**不注册 input 设备**，所以遥控在 ES 里原本完全无效。

`/etc/init.d/S94a4-ird`（早于 S95 启动）+ `/storage/a4-ird` 的做法是：
解绑原驱动 → 直接操作红外块（开时钟、按 NEC 时序采样 `IR_DATAL`）→ 把按键
**注入一个 uinput 虚拟手柄**，名字 `A4 IR Remote`，GUID 与 `es_input.cfg` 里那条对应。

⇒ 所以 ES 里那个"手柄"其实一半是遥控：

| 设备 | jsN | 在 ES 里 | 在游戏里 |
|---|---|---|---|
| `A4 IR Remote`（红外桥） | 视枚举顺序（当前 js1） | 就是你的遥控，方向/确认/返回都能用 | **不占玩家位**（`a4-joymap` 永远排除） |
| 实体手柄（ZhiXu / X360） | 当前 js0 | 也能导航 | **P1**（joymap 按物理手柄顺序分配 P1~P4） |

按键映射表在 `/storage/.config/a4-ir/keys.map`，红外桥日志 `/storage/ird.log`。
> 遥控失灵先看 `/storage/ird.log`，再 `ps | grep a4-ird`。注意 S94a4-ird 必须早于 S95emuelec：
> 它是靠"赶在 ES 启动前把虚拟手柄建好"才有用的，顺序错了遥控就没反应。

### 4.5 玩家端口自动分配

`jsN` 编号随开机顺序变化。`a4-joymap.sh` 已挂进 `run-retroarch.sh`，
每次启动游戏前按实际编号分配 P1~P4（排除红外遥控），解决"一手柄控两人 / 投币翻倍"。
> 注意：未占用的玩家位 index 必须写成"手柄数+1"，写 `99` 会让 RetroArch **段错误**（实测 139）。

### 4.6 声音断续（已修复）

原缓冲只有 2~5ms（`delay` 多次掉到 0 = DMA 跑空）。
改为 `audio_driver=alsathread` + `audio_latency=128`，`delay` 稳定在 75~100% 满。

### 4.7 游戏放在哪（三个入口，别搞混）

ES 里能看到的街机入口有三个，指向三个不同位置：

| ES 里显示名 | 实际路径 | 刷机后 |
|---|---|---|
| **TF Card - Arcade (FinalBurn Neo)** | `/media/emuelec-tf/EmuELEC/roms/fbneo` | ✅ **保留**（TF 不被刷） ← **推荐用这个** |
| Android Storage - Arcade | `/storage/android-roms/roms/fbneo`（bind 到安卓 `/data/media/0/EmuELEC`） | ❌ 被 `format userdata` 清空，空系统自动隐藏 |
| Arcade (FinalBurn Neo) | `/storage/roms/fbneo`（内部 p9，只有 24 MB 余量） | 空 |

**现在游戏已全部放在 TF 卡**（10 个 zip / 337.7 MB），所以**刷完机开机就能玩**：

```
/media/emuelec-tf/EmuELEC/roms/fbneo/      ← 游戏（10 个 zip）
/media/emuelec-tf/EmuELEC/bios/            ← BIOS（neogeo.zip + fbneo/）
```

> BIOS 目录要注意：`run-retroarch.sh` 按 **ROM 所在盘**选 BIOS，
> 用 TF 上的 ROM 时读的是 `/media/emuelec-tf/EmuELEC/bios`，不是 `/storage/roms/bios`。
> 日志里能看到 `HiSTB launch BIOS path=/media/emuelec-tf/EmuELEC/bios`。

**加新游戏**：往 `/media/emuelec-tf/EmuELEC/roms/fbneo/` 里丢 zip（或卡插电脑放 `EmuELEC/roms/fbneo/`），
然后重启前端 `/etc/init.d/S95emuelec restart`（ES 只在启动时扫目录）。

TF 剩余约 850 MB，放 FBNeo 全集（4.0 GB）不够，需要挑着放或换大卡。

### 4.8 显示限制（已知，未解）

HDMI 固定 **1080P50**，NeoGeo/CPS 的 59Hz 内容被压到 50fps。驱动层锁死，用户态改不了：
`EE_VIDEO_MODE` / `global.videomode` / `fb0/mode` / `hi_fb.video` 全部无效。
唯一路径是改 U-Boot 启动参数（有风险，未做）。影响是帧率上限 50，不影响可玩性。

## 六、常见问题

**Q：刷完开机，安卓里没有「温度调节」图标？**
`userdata/app/com.a4.tune-1.apk` 由 PackageManager 首启扫描 `/data/app` 自动注册，
首启需要 1~2 分钟。没有的话重启一次。

**Q：App 点了没反应？**
下拉状态看 `watch` 是否"已启动"。未启动说明 `install-recovery.sh` 没跑（或被杀），
可用 root 手动 `busybox setsid sh -c 'while true; do sh /system/xbin/a4-uv watch; sleep 3; done' &`。

**Q：降压后更热？**
`a4-uv on` 会把 OPP 钉在 1.0GHz（丢掉 DVFS 降频），所以**空闲**反而可能高 1~2 °C；
只有在持续负载（视频/硬解）下才有 4 °C 收益。日常轻载想凉快，用 `a4-uv off`。

**Q：游戏列表看不出选中？**
已修复，选中项是白色。

**Q：按 LB+Start 弹菜单而不是退出？**
说明 `input_menu_toggle_btn` 和 `hotkey` 撞键了。`a4-pad show` 对照三处映射，
确认 `input_menu_toggle_btn = "nul"`。

**Q：WiFi 连不上？**
1. `a4-wifi status` 看日志 2. 确认安卓里能连 3. `a4-wifi restart`
> 注意：刷机后安卓没有 WiFi 记录，第一次要在安卓里连一次，EmuELEC 才有得导入。

**Q：插上手柄没反应？**
ES 只在启动时枚举设备。正常情况下 `a4-hotplug` 会在 3~10 秒内自动重启前端（屏幕闪一下回列表）。
没反应就依次：`/etc/init.d/S96a4-inputrecover restart` → `/etc/init.d/S95emuelec restart` → `reboot`；
同时看 `/storage/ee/logs/a4-hotplug.log` 有没有 `added: eventN`。

**Q：遥控失灵？**
遥控是 `a4-ird` 注入的虚拟手柄。先 `ps | grep a4-ird`，再看 `/storage/ird.log`；
确认 `/etc/init.d/S94a4-ird` 存在且在 `S95emuelec` 之前（编号必须更小）。

**Q：想两个人一起玩？**
插第二支手柄 → 等前端自动重启 → `a4-joymap` 会按物理顺序分 P1/P2（各占自己的 jsN）。
遥控 `A4 IR Remote` 永远不占玩家位。若两人按键串台，先 `a4-pad show` 看三处映射。
确认 `audio_driver = "alsathread"`、`audio_latency = "128"`。

## 九、本次核对方式（为什么能保证"刷完和现在设备一致"）

不是靠记忆，是把设备上 `/system` 全部 1587 个文件算 md5，逐个和包内比：

```
设备文件数 1587 / 包内 system 文件数 1580
内容不同：5  → 全部纳入本包（wifi_recover / build.prop / install-recovery / init.bigfish / libstagefright）
设备多出 ：7  → 其中 5 个有用文件已纳入（A4DualBoot.apk / a4-switch / uvmode.sh），
               2 个是运行期产物与备份（blkid.tab*、install-recovery.sh.a4bak/.bak-1021）
```

打包后再回放校验：

```
条目数 1609（原 1598 + 11）
SF 头 manifest 摘要匹配: True
签名验证: PASS (RSA/SHA1 over CERT.SF)
刷机后与设备不一致的文件: 2 → etc/init.bigfish.sh、etc/install-recovery.sh（有意改动）
```

另外对 EmuELEC 镜像本身做了 `debugfs` 查证（确认输入/遥控守护真的在镜像里，不会被刷丢）：

```
debugfs -R "stat /storage/a4-hotplug"        emu_rootfs.img  → 473744 B, 0755
debugfs -R "stat /storage/a4-ird"            emu_rootfs.img  → 379272 B, 0755
debugfs -R "stat /etc/init.d/S94a4-ird"      emu_rootfs.img  →   2003 B, 0755
debugfs -R "stat /etc/init.d/S96a4-inputrecover" emu_rootfs.img → 1549 B, 0755
debugfs -R "stat /opt/emuelec/bin/a4-joymap.sh"  emu_rootfs.img → 2060 B, 0755
```
